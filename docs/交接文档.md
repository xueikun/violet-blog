## 一、这是什么

一个纯静态的二次元风格个人博客。站名「薇尔莉特」取自《紫罗兰永恒花园》,整体视觉走紫罗兰 + 火漆金 + 衬线字体的书信气质。

**核心用途**:记录技术笔记、生活随笔、追番感想。

**内容载体**:Markdown 文件。发一篇文章 = 新建一个 `.md` 文件 + `git push`。

**部署目标**:`https://xueikun.github.io/violet-blog/`

### 技术栈

| 项 | 值 |
| --- | --- |
| 框架 | Astro 5.18.2(静态输出) |
| 依赖总数 | **1 个**(只有 `astro`) |
| 样式 | 原生 CSS + CSS 变量 |
| 交互 | 原生 JavaScript,无框架 |
| 评论 | giscus(GitHub Discussions) |
| 站内搜索 | 构建期生成静态索引 JSON + 前端内存检索 |
| 部署 | GitHub Pages + GitHub Actions |

## 二、30 秒上手

```bash
cd "E:/workFile/个人博客"
npm install
npm run dev -- --port 4321 --host 127.0.0.1
```

然后访问:

**http://localhost:4321/violet-blog/**

### ⚠️ 三个必须记住的命令细节

1. **必须带 `/violet-blog/` 前缀**。站点部署在子路径下,直接访问 `http://localhost:4321/` 会打不开,这不是故障。
2. **必须加 `--host 127.0.0.1`**。否则只监听 IPv6 的 `[::1]`,用 `127.0.0.1` 访问不通。
3. **本机 curl 探测要加 `--noproxy '*'`**。否则会走系统代理返回 502。

### 其他命令

```bash
npm run build      # 构建到 dist/,约 15-70 秒
npm run preview    # 预览构建产物
```

## 三、技术决策与理由

这部分是交接的重点——**为什么这么做**,避免后来者改错方向。

| 决策 | 理由 |
| --- | --- |
| **选 Astro,不用 Next.js / Vue** | 纯静态内容站,没有任何服务端逻辑。Astro 默认零 JS,首屏最快 |
| **不引入 React/Vue** | 当前所有交互(打字机、粒子、倾斜、主题切换)用原生 JS 完全够。引入框架会白加几十 KB 首屏体积。真需要复杂状态时再加 |
| **依赖只有一个 astro** | RSS / sitemap / robots 全部用 Astro 的 API Route 手写,不装 `@astrojs/rss`、`@astrojs/sitemap`。理由是这台机器上 npm 安装出过问题(见第九节),能不加依赖就不加 |
| **颜色只在 `tokens.css` 定义** | 换肤只改一个文件。已实践验证两次:樱花粉 → 紫罗兰全套,组件一行没动 |
| **站内链接全走 `url()`** | 站点在子路径下部署,手写路径会"本地正常、线上 404",极难排查。统一走工具函数后,换域名只需改配置 |
| **卡片倾斜用 CSS 变量驱动** | JS 直接写 `transform` 会和 `:hover` 的上浮动画打架,表现为"倾斜一顿一顿"。改用 `--rx/--ry/--ty` 分离职责 |
| **评论用 giscus** | 零后端、零数据库、零成本。数据存在自己的 GitHub 仓库里,不经过第三方 |
| **按钮色单独用 `--btn-*` 变量** | 紫罗兰 `#8b7bc7` 配白字对比度只有 3.6:1,达不到无障碍标准 4.5:1。按钮底色单独用更深的 `#6f5ca8`(5.6:1),深色模式反过来用亮紫底 + 深字(7.2:1) |
| **搜索索引在构建期生成** | `src/pages/search-index.json.ts` 把 Markdown 压成纯文本 JSON。运行时零后端、零依赖,也不需要第三方搜索服务。文章到几百篇再考虑分片 |
| **og:image 用无头 Chromium 渲染 HTML** | 引 sharp / canvas 要加依赖(违背"只装 astro"的约定)。用 `scripts/og-card.html` + 系统里已有的 Chromium 截图,排版和站点视觉天然一致,改文案只要重跑 `npm run og` |
| **标签 URL 用 slug 而非原始文字** | `Spring Boot` → `spring-boot`。中文标签保持原字符(浏览器自动编码),避免引入拼音库 |

## 五、七条必须遵守的约定

改这个项目之前,请先看完这七条。**每一条都是踩过坑总结出来的**。

### 1. 颜色只在 `tokens.css` 定义

组件里**禁止写死色值**,一律 `var(--primary)` 这样引用。

想让颜色跟随主题变化,就必须用变量。直接写 `color: #8b7bc7` 的组件在深色模式下会瞎眼。

### 2. 站内路径必须走 `url()`

```astro
---
import { url } from "../utils/url";
---
<a href={url("posts/")}>文章列表</a>   <!-- ✅ -->
<a href="/posts/">文章列表</a>          <!-- ❌ 线上 404 -->
```

**症状很迷惑**:本地 dev 看着完全正常,一部署就全站 404。RSS / sitemap 里要用 `absoluteUrl()`。

### 3. 新增动效必须做三重降级

```js
const reduceMotion = matchMedia("(prefers-reduced-motion: reduce)").matches;
const noHover = matchMedia("(hover: none)").matches;   // 触屏
const smallScreen = matchMedia("(max-width: 820px)").matches;
```

- 系统开了「减弱动效」→ **全关**
- 触屏设备 → 关倾斜
- 窄屏 ≤820px → 关粒子

目的不只是体验,还有性能——手机上跑 canvas 粒子和 Live2D 会明显卡顿。

### 4. 卡片倾斜用 CSS 变量,别用 JS 写 transform

`.sticker-hover` 的 `transform` 由 `--rx / --ry / --ty` 三个变量组成。JS 只允许设置前两个:

```js
node.style.setProperty("--ry", `${deg}deg`);   // ✅
node.style.transform = `rotateY(${deg}deg)`;   // ❌ 会覆盖 :hover 的上浮
```

### 5. 改动依赖后,`package-lock.json` 必须一起提交

CI 用的是 `npm ci`,强依赖 lock 文件。只改 `package.json` 不提交 lock,CI 会直接失败。

### 6. 客户端脚本里别直接用 `import.meta.env.BASE_URL`

它在客户端是**不带尾斜杠**的 `/violet-blog`,拼出来是 `/violet-blogsearch-index.json` 这种坏地址 —— 本地跑起来看不出异常,请求静默失败,数据永远是空的。

```js
fetch(`${import.meta.env.BASE_URL}search-index.json`);  // ❌ /violet-blogsearch-index.json
fetch(url("search-index.json"));                        // ✅ 走 utils/url.ts
```

`url.ts` 里的 `basePrefix()` 会自动补斜杠,这就是它存在的理由。

### 7. JS 注入的 DOM,对应 CSS 必须用 `:global()`

Astro 的组件样式默认带作用域属性,只对**模板里写死的元素**生效。`Search.astro` 里的结果列表是 `innerHTML` 拼出来的,元素上没有那个属性,不加 `:global()` 就是「逻辑全对、样式全丢」——表现为内容挤成一坨,极难第一眼看出来。

```css
.sm-body :global(.sm-hit) { ... }   /* ✅ */
.sm-hit { ... }                     /* ❌ 命中不了注入的节点 */
```

同理,在 `.astro` 的 `<script>` 里写模板字符串时,颜文字里的**反引号**会提前闭合字符串(构建期才报错,提示还指不到那行)。换成全角 `｀`。

## 六、如何写一篇文章

### 第一步:新建文件

`src/content/posts/你的文章.md`,文件名会成为 URL:`/posts/文件名/`

建议用英文短横线命名(如 `springboot-keng.md`),中文文件名会让 URL 变成一长串百分号编码。

### 第二步:写 frontmatter

```yaml
---
title: "文章标题"
date: 2026-09-27
excerpt: "一两句话摘要,会显示在卡片上"
category: "技术笔记"
tags: ["Java", "踩坑"]
mood: "元气"
top: false
draft: false
---
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `title` | ✅ | 标题 |
| `date` | ✅ | 日期,决定排序 |
| `excerpt` | ✅ | 摘要,卡片上显示两行 |
| `category` | | 分类,默认「未分类」 |
| `tags` | | 标签数组,用于筛选 |
| `mood` | | 卡片右上角心情角标:元气 / 摸鱼 / 发呆 / 燃 / 平静 |
| `top` | | 置顶 |
| `draft` | | 草稿,不会被打包上线 |
| `cover` | | 封面图路径 |

字段定义在 `src/content.config.ts`,写错了构建时会报错提示。

### 第三步:正文

就是普通 Markdown。项目已经配好的样式:

- 代码块自动高亮(Shiki),**跟随深浅主题切换**
- 表格、引用、列表都有专门样式
- 引用块带衬线引号装饰
- 图片自动圆角 + 描边

### 第四步:提交

```bash
git add .
git commit -m "post: 文章标题"
git push
```

```json
  "author": "龙哥",
  "bio": "写 Java 的人,偶尔也写点别的",
  "since": "2026"
}
```

改文案不用碰代码。

### 部署地址 —— `astro.config.mjs`

```js
site: 'https://xueikun.github.io',
base: '/violet-blog',
```

**换域名的步骤**:改这两行(`base` 改成 `'/'`)+ 放 `public/CNAME` 文件。所有 `url()` 会自动适配,组件不用动。

### 评论 —— `src/data/comments.json`

```json
{
  "enabled": true,
  "repo": "xueikun/violet-blog-comments",
  "repoId": "R_kgDOUsvC-g",
  "category": "General",
  "categoryId": "DIC_kwDOUsvC-s4DGb4B"
}
```

两个 ID 的**免 token 获取方法**(已验证):

- `repoId` ← `https://api.github.com/repos/OWNER/REPO` 响应里的 `node_id` 字段
- `categoryId` ← `https://giscus.app/api/discussions/categories?repo=OWNER/REPO&category=`

**分类必须是 `General`,不能改成 `Announcements`**。后者只有管理员能发起新讨论,会导致「某篇文章第一个人评论不了」的死锁。

## 九、已知的坑(环境相关)

这台机器上的 WorkBuddy 环境有一些特殊行为,遇到报错先对照这里,别急着改代码。

| 现象 | 真相 | 解法 |
| --- | --- | --- |
| `npm install` 报 `spawnSync node.exe EBUSY` | Windows 瞬时文件锁,二进制其实已就位 | **忽略**。直接 `npm run build` 验证 |
| 构建报 `genie-trash ETIMEDOUT` 退出码 1 | WorkBuddy 回收站拦截器超时 | **重试一次即可** |
| 改 `base` 或 Vite 配置后 dev 起不来 | Vite 要重建依赖缓存,需删 `node_modules/.vite/deps`(常超 50 文件),被批量删除保护拦下 | 手动 `rm -rf node_modules/.vite` 再启动 |
| curl 本机服务返回 502 | 走了系统代理 | 加 `--noproxy '*'` |
| `127.0.0.1:4321` 不通但 `localhost:4321` 通 | dev 默认只监听 IPv6 | 启动时加 `--host 127.0.0.1` |
