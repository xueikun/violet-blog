# 评论系统接入说明(giscus)

评论数据存在你自己的 GitHub 仓库里,不需要服务器,不需要数据库,免费。

---

## 一、准备仓库

1. 建一个**公开**仓库,比如 `violet-blog-comments`
   - 必须公开,giscus 要读它
   - 可以和你放代码的仓库分开,避免评论污染提交记录

2. 给这个仓库**开启 Discussions**
   - 仓库页 → Settings → 找到 Features 区块 → 勾选 **Discussions**

3. 选一个分类
   - 开启 Discussions 后仓库会自动生成几个默认分类,**直接用 `General` 就行**
   - ⚠️ **不要选 `Announcements`**:那个类型只有管理员能发起新讨论
   - 后果是:某篇文章还没有对应讨论串时,第一个想评论的人会卡住说不了话,得你手动为每篇预先建串
   - 先按 `General` 跑,以后真被垃圾评论骚扰,再换 `Announcements` 并手动预建讨论

## 二、安装 giscus App

访问 https://github.com/apps/giscus → Install → 选择「Only select repositories」→ 勾选上面那个仓库 → Install。

## 三、拿到 4 个参数

打开 https://giscus.app/zh-CN ,依次填:

| 页面字段 | 填什么 |
| --- | --- |
| 仓库 | `你的用户名/仓库名`,例如 `dragon/violet-blog-comments` |
| 页面 ↔ Discussion 映射 | 文章页选 `pathname` |
| Discussion 分类 | 选 `General`(见上面第 3 点的原因) |
| 特性 | 按需勾,建议勾「反应」「评论框在上方」 |

填完后页面下方会生成一段 `<script>` 代码,里面就有你要的 4 个值。

## 四、填入配置

打开 `src/data/comments.json`,改成:

```json
{
  "enabled": true,
  "repo": "xueikun/violet-blog-comments",
  "repoId": "R_kgDOxxxxxxx",
  "category": "General",
  "categoryId": "DIC_kwDOxxxxxxxx",
  "reactionsEnabled": "1",
  "inputPosition": "top",
  "lang": "zh-CN"
}
```

**四个必填项**:`enabled` 改 `true`,`repo` / `repoId` / `categoryId` 从 giscus.app 抄过来。

改完重启一下 dev server。

---

## 已经替你处理好的部分

这些不用你操心,组件里都做完了:

- **懒加载** — 评论 script 要滚动到评论区附近才注入,不拖慢首屏
- **主题跟随** — 点站点右上角的日/夜切换,评论区会同步换色(靠 `postMessage` 通知 iframe)
- **未配置时的提示** — 开发环境会显示一张说明卡,生产环境只显示「评论暂未开放」,不会露出配置引导
- **本地化参数** — 语言已设为 `zh-CN`,评论框位置在上方

## 用在哪两处

| 位置 | 映射方式 | 效果 |
| --- | --- | --- |
| 文章详情页底部 | `pathname` | 每篇文章自动对应一个独立 Discussion |
| `/guestbook/` 留言板 | `specific` + `term="guestbook"` | 全站共用一个长期讨论串 |

想调整,改 `Giscus.astro` 的 `mapping` / `term` 参数即可。

---

## 注意:网络可达性

`giscus.app` 的脚本是境外资源。国内访问有时候会慢或者加载不出来。

如果发现评论区长期空白,有两个办法:

1. **自建 giscus**:用 Cloudflare Workers 或 Vercel 部署一份,把 `script.src` 换成你自己的域名(需要建一个 GitHub App,约 10 分钟)
2. **换方案**:用 Waline(Vercel + 数据库)或 Twikoo(云函数),但那就需要后端了

真遇到问题再说,先按上面配好试。
