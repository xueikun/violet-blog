# 部署说明(GitHub Pages + 自定义域名)

目标:推到 `main` 分支 → 自动构建 → 自动发布到 `https://xuegungun.cn`

---

## 一、创建代码仓库

在 GitHub 上建一个仓库,**公开**(GitHub Pages 免费版要求公开,除非升级 Pro)。

- 仓库名建议用 `blog` 或 `violet-blog`
- **不要**用 `xueikun.github.io` 这种名字——那是"用户站点"命名法,会和自定义域名冲突,也没必要
- 建的时候什么都别勾(不要 README、不要 .gitignore),否则本地推送会打架

> 注意:评论用的 `violet-blog-comments` 仓库是另一个,别混。

## 二、关联远程并推送

在项目目录执行(把 `你的仓库名` 换成实际名字):

```bash
git remote add origin https://github.com/xueikun/你的仓库名.git
git push -u origin main
```

推送时如果要求登录,用 GitHub 的 **Personal Access Token** 当密码(GitHub 早就不支持账号密码直推了)。

第一次推送会触发 GitHub Actions 自动跑一遍构建,**这一步大概率会失败**——因为 Pages 还没开启,属正常现象,继续往下做。

## 三、开启 GitHub Pages

仓库 → **Settings** → 左侧 **Pages** →

- **Source** 选 **GitHub Actions**(不要选 "Deploy from a branch")

保存即可。这个设置我已经在项目里放好了对应的工作流文件 `.github/workflows/deploy.yml`,不用你手工创建。

## 四、配置 DNS 解析

到你的域名服务商(阿里云 / 腾讯云 / Cloudflare 等)的 DNS 解析页面,添加以下记录。

### 根域名 xuegungun.cn —— 必须用 A 记录

| 记录类型 | 主机记录 | 记录值 |
| --- | --- | --- |
| A | `@` | `185.199.108.153` |
| A | `@` | `185.199.109.153` |
| A | `@` | `185.199.110.153` |
| A | `@` | `185.199.111.153` |

想同时支持 IPv6,再加 4 条 AAAA:

| 记录类型 | 主机记录 | 记录值 |
| --- | --- | --- |
| AAAA | `@` | `2606:50c0:8000::153` |
| AAAA | `@` | `2606:50c0:8001::153` |
| AAAA | `@` | `2606:50c0:8002::153` |
| AAAA | `@` | `2606:50c0:8003::153` |

### www 子域名 —— 用 CNAME

| 记录类型 | 主机记录 | 记录值 |
| --- | --- | --- |
| CNAME | `www` | `xueikun.github.io` |

> **为什么根域名不能用 CNAME?** DNS 规范不允许 apex 域名使用 CNAME 记录。必须用 A 记录。

## 五、绑定自定义域名

仓库 → Settings → Pages → **Custom domain** 填 `xuegungun.cn` → Save。

项目里 `public/CNAME` 已经写好了这个域名,构建后会输出到站点根目录,GitHub 会自动识别。**你手动填一次更保险**(有时首次识别需要触发)。

然后勾选 **Enforce HTTPS**。等证书签发(通常几分钟到几小时),HTTPS 就生效了。

## 关于 .cn 域名,两件必须提前知道的事

### 1. 备案问题

严格来说,**使用境外服务器不需要 ICP 备案**。GitHub Pages 是境外的,所以指向它不触发备案要求。

但要注意:如果你的 DNS 解析服务在国内厂商(阿里云、腾讯云、华为云等),部分地区或时期会对**指向境外 IP 的 .cn 域名**做限制提示。真遇到了,解决办法是**把 DNS 换到 Cloudflare**,不再走国内解析商。

### 2. 访问速度问题

这是更现实的坑:**GitHub Pages 在国内的访问速度不稳定**,有时快有时慢,偶尔会被干扰。

`.cn` 域名 + GitHub Pages 这个组合,技术上没问题,但体验上不保证。

**如果后面发现访问慢或者经常打不开**,出路有两条:

| 方案 | 说明 |
| --- | --- |
| Cloudflare 代理 | 域名 DNS 转到 Cloudflare,开启橙色云朵代理。能改善一部分,但免费版国内速度仍然一般 |
| 国内云服务器 | 速度最快最稳,但**必须 ICP 备案**(约 1-2 周),还要自己配 Nginx 和证书 |

建议先用 GitHub Pages 跑起来,真实体验一段时间再决定要不要换。反正 Astro 是纯静态站,换托管方只是改 DNS,代码一行不用动。

## 日常发布流程

以后写文章就三步:

```bash
# 1. 新建一个 md 文件
#    src/content/posts/你的文章.md

# 2. 提交
git add .
git commit -m "post: 文章标题"

# 3. 推送,自动部署
git push
```

推完等一分钟左右,GitHub Actions 跑完就上线了。想确认进度,去仓库的 **Actions** 标签页看。

### 文章模板

新建 md 文件时,头部照这个写:

```yaml
---
title: "文章标题"
date: 2026-09-27
excerpt: "一两句话摘要,会显示在卡片上"
category: "技术笔记"
tags: ["标签1", "标签2"]
mood: "元气"
---
```

`mood` 会显示成卡片右上角的心情角标,可选:元气 / 摸鱼 / 发呆 / 燃 / 平静。

想置顶加 `top: true`;写草稿加 `draft: true`(草稿不会被构建)。
